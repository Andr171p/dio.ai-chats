# DIOS AI — веб-интерфейс ИИ-чатов

React 19 · TypeScript · Vite · Zustand · Streamdown/Shiki · SCSS Modules. Правила архитектуры — в [AGENTS.md](AGENTS.md).

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
```

В dev-режиме Vite проксирует запросы: `/auth-api` → сервис авторизации DIO desk (`:8001`), `/chats-api` → сервис чатов (`:8000`). Сервис чатов не отдаёт CORS-заголовки, поэтому фронтенд всегда ходит в API через свой origin.

| Скрипт | Что делает |
| --- | --- |
| `npm run build` | проверка типов и production-сборка |
| `npm run preview` | локальный просмотр сборки (с тем же прокси) |
| `npm run lint` / `lint:fix` | ESLint, включая правила слоёв FSD |
| `npm run typecheck` | только проверка типов |
| `npm run format` / `format:check` | Prettier |

Переменные окружения — в [.env](.env): `VITE_AUTH_API_URL`, `VITE_CHATS_API_URL` (базовые адреса API для браузера), `VITE_TRUSTED_ORIGINS` (сервисы DIOS, ссылки на которые открываются без предупреждения) и `AUTH_API_TARGET`, `CHATS_API_TARGET` (куда проксирует dev-сервер). Локальные переопределения — в `.env.local`.

## Архитектура

Слои FSD: `app → pages → widgets → features → entities → shared`. ESLint запрещает импорт вышележащих слоёв, соседних слайсов и обход public API (`index.ts`); сущности могут ссылаться на типы друг друга только через `import type`.

- **Состояние** — сторы Zustand в `model/` сущностей и фич. Действия — функции модуля, которые напрямую вызывают `BackendCaller`.
- **`shared/api`** — `BackendCaller` (fetch + авторизация + единый формат ошибок) и менеджер токенов.
- **`features/send-message/api/run-stream.ts`** — RunStream: SSE-поток генерации → типизированные события `run.*`.
- **Навигация** — без роутера: текущий экран хранится в сторе (`shared/lib/navigation`), приложение не трогает адресную строку и может встраиваться виджетом в DIO desk.

## Аутентификация

- Access-токен живёт только в памяти вкладки.
- Refresh-токен хранится в `localStorage` и ротируется при каждом обновлении. Обновление выполняется одним запросом (single-flight) и сериализуется между вкладками через Web Locks, поэтому один refresh-токен никогда не уходит на сервер дважды.
- На 401 запрос повторяется один раз с новым токеном. Ошибки сети не разлогинивают пользователя.
- Выход отзывает токены на сервере и завершает сессию во всех вкладках. Пользовательские сторы при этом сбрасываются.
- Production-сборка содержит CSP: `script-src 'self'`, без `unsafe-eval`. Абсолютные адреса API из env попадают в `connect-src`.
- Ответы модели проходят санитизацию Streamdown (`rehype-sanitize`, `rehype-harden`), Mermaid работает с `securityLevel: 'strict'`, переход по внешним ссылкам требует подтверждения.

Долгосрочно рекомендуется перенести refresh-токен в httpOnly-cookie на стороне сервиса авторизации: тогда он станет недоступен JavaScript.

## Markdown в ответах

GFM (таблицы, чек-листы, сноски-источники), подсветка кода Shiki с копированием и скачиванием, формулы KaTeX (включая `\( … \)` и `\[ … \]`), диаграммы Mermaid в палитре DIOS, корректный рендер незакрытой разметки во время стриминга.

## Что ждёт API

Элементы макета, для которых пока нет эндпоинтов, показаны неактивными с подсказкой «Скоро»: проекты, вложения, голосовой ввод, оценка ответа, повторная генерация, ветки, DIOS Auto, личные и локальные модели, MCP-серверы.

## Деплой

Фронтенд ожидает оба API на своём origin по путям `/auth-api` и `/chats-api`. Их нужно проксировать reverse proxy так же, как это делает dev-сервер, либо указать абсолютные URL в env, если на сервисах настроен CORS.
